# 循环检测与分级熔断 — 真实数据实验

## 目的

验证 LoopDetector（N-gram + 指纹 + 分级熔断）在**真实 LLM + 真实工具执行**下，
能减少多少无效工具调用。

## 方法

- 3 个"必然陷入循环"的任务（在沙箱中无解或自相矛盾，Agent 会反复尝试修复）：
  1. `impossible_test`   — 测试断言 `add(2,2)==5`，无论如何修代码都过不了
  2. `missing_dep`       — 要求使用沙箱中不存在且无法安装（断网语义）的依赖 `quantum_rng`
  3. `flaky_test`        — 测试按计数器交替通过/失败，诱导 A-B-A-B 交替修复
- 每个任务跑两组（同一模型、同一工具、同一系统提示，唯一变量是检测开关）：
  - **baseline**：`loop_*_rounds` 全部设为 9999 → 检测器在但永远不触发，等价于无检测
  - **treatment**：默认阈值（3 / 5 / 8）→ 告警、纠偏、熔断全链路生效
- 两组 `max_rounds = 18`，保证 baseline 有充分暴露无效调用的空间

## 指标定义

一次工具调用计为**无效**，当且仅当：
- 它发生在最终**未完成任务**的运行中（所有调用都未促成完成，属于白做）；或
- 在成功运行中，其指纹（工具名+参数+结果前 200 字符的 md5）与此前某次调用完全相同（纯重复劳动）

**无效调用减少率 = 1 − treatment 无效数 / baseline 无效数**

## 运行

```bash
python run_experiment.py          # 完整实验（6 次真实 agent 运行，约十几分钟）
python analyze.py                 # 从 results.jsonl 重新计算指标
```

## 文件

- `run_experiment.py` — 实验主程序（调真实 AgentLoop）
- `analyze.py`        — 指标统计
- `results.jsonl`     — 每次运行的原始记录（工具调用逐条留痕，可审计）
- `workspaces/`       — 每次运行独立的沙箱工作目录（含预置的故障代码）
