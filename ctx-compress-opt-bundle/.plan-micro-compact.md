# 计划：新建 ctx-compress-opt/micro_compact.py 并接入 compress.py

## 目标
把 `micro_compact_time.py` 的「按时间触发」改造成一个**按阈值触发的渐进式微压缩** `micro_compact.py`，
放在 `_compress_context` 的最前面（超大工具剪裁之后、按轮 LLM 摘要之前）先跑一遍。
`_compress_context` 签名不变（CLAUDE.md 约束）。

## 触发时机（compress.py 内）
当前顺序会调整为：
1. `current_tokens <= max_tokens` → 原样返回。
2. `_trim_oversized_tools_via_budget`（超大工具转存+预览）→ 若达标返回。
3. **【新增】`current_tokens > max_tokens` → 调用 `micro_compact(messages, max_tokens)` 本地清理 → 若达标返回。**
4. 仍超限 → 走原有的按轮 LLM 摘要。
5. 摘要后仍超限 → `_handle_single_round_overflow`（保持不动）。

即：**先 micro_compact，随后再摘要**。micro_compact 不触碰系统消息、运行时上下文标记、已压缩摘要区。

## 新文件 ctx-compress-opt/micro_compact.py

### 保留 / 复用
- `COMPACTABLE_TOOLS`：用 micro_compact_time.py 的 hermes 真实工具名集合。
- 占位串常量、compactable id 收集、多模态/已清理守卫。
- token 估算复用 compress.py 的 `_estimate_tokens`（惰性 import，避免循环依赖）。
- **不保留磁盘路径**：清理已转存块也统一换成普通占位串（不抠 read_file 路径），
  因此不需要 `_cleared_content_for` / `_extract_persisted_path` / `_CLEARED_WITH_PATH_PREFIX`。

### 删除
- 所有「时间触发」相关：`gap_threshold_minutes`、`evaluate_time_based_trigger`、
  `_last_activity_ms`、`_parse_timestamp_ms`、`now_ms`/`last_activity_ms` 参数。
- 跨轮冻结 state（`MicrocompactState`/重放段）——本地一次性清理，不需要。

### 主入口
```python
def micro_compact(messages: list[dict], max_tokens: int) -> list[dict]:
    """阈值触发的渐进式微压缩：按优先级逐级清理，每步后重估，达标即返回。
    只作用于传入列表的副本，产出新 dict；不改系统消息/运行时标记/已压缩摘要区。"""
```

### 结构切分（复用 compress.py 的掐头去尾逻辑）
在函数内先算出三段边界（与 `_compress_context` 同一套判断）：
- `system_msg`：首条 system，永远保留。
- `_RUNTIME_CONTEXT_TAG`：第二条运行时上下文标记，永远保留。
- `start_idx_compressed`：已有 `[Context Summary]` 摘要区，永远保留。
- 之后用 `_split_into_rounds` 切成轮次；**最后一轮 = 当前进行中的 user session**。

### 级联步骤（按优先级，每步后 `fits()` 检测，达标即返回）

**Step 0 — 掐头去尾（结构裁剪）**
- 当前 session（最后一轮）：**保留最近 5 条消息**，更早的并入「可清理历史」。
- 保护区（system + 运行时标记 + 已压缩摘要区 + 当前 session 最近 5 条）不参与后续清理。

**Step 1 — 本地清理旧 tool result**
- 对「可清理历史」里的 COMPACTABLE_TOOLS tool result，内容清空成占位串
  （已转存块保留磁盘路径）。当前 session 最近 5 条内的 tool result 不动。

**Step 2 — 瘦身旧 tool call 参数**
- 把历史 assistant 的 COMPACTABLE_TOOLS tool_calls 的 `arguments` 换成占位/空
  （execute_code→`{"code":""}`、terminal→`{"command":""}`、其余→`{}`）。当前 session 不动。

**Step 3 — 删除除当前轮外的 reasoning_content**
- 清空所有非当前 session 消息的 `reasoning_content`。**最新一轮 user 的 reasoning 保留。**
- （放在 tool result 清理之后，符合你的要求。）

**Step 4 — 占位符兜底（更激进）**
- 若仍超限：把范围放宽，对更早的 tool result 用占位符方式全部清空（含 Step1 未覆盖的），
  tool call 参数也全部占位。这是本地最后一档，不删消息（删除交给后续摘要/兜底）。

- micro_compact 结束后无论是否达标都返回；未达标则由 `_compress_context` 继续走 LLM 摘要。

## compress.py 改动
- 新增惰性 import：`from micro_compact import micro_compact`（同 `_trim_oversized_tools_via_budget`
  的 sys.path 处理，加载本目录副本）。
- 在超大工具剪裁的达标检查之后、结构切分之前，插入：
  ```python
  messages = _run_micro_compact(messages, max_tokens)   # 防御式包装，异常降级原样返回
  current_tokens = _estimate_tokens(messages)
  if current_tokens <= max_tokens:
      return messages
  ```
- 包装函数 `_run_micro_compact` 仿 `_trim_oversized_tools_via_budget`：try/except、日志、失败原样返回。
